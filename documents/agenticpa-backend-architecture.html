A real graph-level interrupt, not a UI-faked pause: the graph literally cannot reach summarizer while needs_human_review=True. State is checkpointed to Postgres (thread_id=case_id) — survives across separate HTTP requests and process restarts.

Reading this diagram

Every LLM call has a fallback Extraction confidence unknown → treated as low, not high. Peer-Review rationale fails → hard gates still stand. Summarizer fails → templated letter. Never silent auto-approval.
Hard gates are asymmetric The LLM rationale layer in Peer-Review can only escalate (add reasons), never downgrade a fired flag back to auto-approve.
Checkpointer ≠ audit log PostgresSaver only stores enough to resume an interrupt. case_runner.py separately mirrors state into queryable cases / audit_logs tables for the API/Admin dashboard.
Routing hints vs. hard gates relevant_agents only decides which checks run; it never decides whether a case is safe to auto-approve — that's Peer-Review's job alone.

Why agents, not one prompt: the deterministic hard gates (20% cost variance, 0.70 similarity, 85% confidence) are what a single LLM call can't guarantee — consistent, auditable, non-hallucinated thresholds. The LLM layers add reasoning and plain-English translation on top of that guarantee; they never replace it.
