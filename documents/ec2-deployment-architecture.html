AgenticPA · Infrastructure

Single-EC2 Docker Compose Deployment

All five services from docker-compose.yml run as sibling containers on one EC2 host — no ECS/EKS, no managed RDS. Traffic enters through the instance's Security Group; only the Nginx-served frontend and FastAPI backend ports are reachable from outside the box.

First deploy · on the EC2 host
# clone + configure
git clone <repo> agentic-pa && cd agentic-pa
cp .env.example .env # set POSTGRES_PASSWORD, REDIS_PASSWORD, GEMINI_API_KEY
 
# build + run all five services
docker compose up -d --build
 
# health
curl http://localhost:8000/health

Security group rules

  • 22 SSH — restrict to your IP/CIDR
  • 80/443 HTTP(S) — frontend, from 0.0.0.0/0
  • 8000 API — only if hitting the backend directly for debugging
  • 5432 / 6379 / 6333 — not exposed outside the Docker bridge network

What's not shown

  • No ALB / Route 53 — instance is reached by its public IP or an A record pointed at it
  • No managed RDS/ElastiCache — Postgres and Redis are the containers, backed by EBS volumes
  • No autoscaling — one instance, one docker compose stack
  • TLS termination (if added) would sit in front of nginx, e.g. Let's Encrypt via certbot

Auth reality check

  • demo login creds are baked into the frontend image at build time (Vite VITE__ args)
  • rotating a demo password means rebuilding the frontend container, not just editing .env at runtime
